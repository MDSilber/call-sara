# Household finance vault — the system

This directory is a household's private financial memory. Any agent working
here reads this file first, then `THESIS.md`. The METHOD (how to advise, how
to pull documents) lives in the `finance` skill; the LOGIC (importers,
queries, checks, report generators) lives in that skill's `tools/`. This
file is the DATA CONTRACT: what goes where, in what shape, so the vault stays
easy to add to, easy to read, and easy to query.

## Read order, every session
1. `CLAUDE.md` (this) — layout and formats.
2. `THESIS.md` — who this household is and what they've agreed. The client.
3. `facts/household/` — profile, liquidity model, institutions,
   beneficiaries, professionals, calendar. The facts that shape advice.
4. `reports/findings.md` — anything currently flagged.

## Layout
```
CLAUDE.md      the system (this file)
THESIS.md      the investment policy statement — the client contract
rules.toml     categorization + account-routing rules (read by the tools AND the agent)
ledger/        the money — Beancount v3, one file per year, main.beancount includes all
facts/         everything that isn't a transaction — one markdown file per thing
  household/   always-read: profile, liquidity model, institutions, beneficiaries,
               professionals, calendar
  people/  accounts/  equity/  policies/  tax/  goals/  misc/
documents/     raw source PDFs/exports, mirroring the account tree — GITIGNORED, on disk only
reports/       GENERATED by the tools. Read these first to answer questions. Never hand-edit.
notes/         advisor memos, agendas, action lists — dated filenames, permanent, hand-written
inbox/         drop zone for unfiled files — GITIGNORED, kept empty
```

## Filing a new document (the pipeline)
1. **Identify** it — institution, account, date range, kind.
2. **File the source** into `documents/` as `YYYY-MM-DD.name.pdf`, under a
   folder mirroring the ledger account
   (`documents/Assets/US/<Institution>/<Owner>/`); tax forms go to
   `documents/tax/<year>/`. Superseded docs move to an `archive/` subfolder;
   originals are never deleted or edited.
3. **Extract**: transactions → `ledger/<year>.beancount` (via the importers,
   categorized by `rules.toml`); statement balances → `balance` assertions;
   non-transaction facts → the right `facts/` file.
4. **Learn the rule**: any categorization you corrected by hand becomes a
   `[[payee_rules]]` entry in `rules.toml`, then re-apply with
   `tools/run recategorize.py`. Never fix the same thing twice.
5. **Check**: `.venv/bin/bean-check ledger/main.beancount` must pass.
6. **Regenerate `reports/`** (`tools/run reports.py`, `tools/run run_checks.py`).
7. **Commit**, and report back in one or two lines.

## Facts format
One folder (or file) per thing, YAML frontmatter + prose. Four fields are
required on every file so anything can be dumped and still be findable:

```yaml
---
type: account        # account | equity | policy | person | tax_year | goals | household | note
date: 2026-01-31     # the as-of date of the facts below
verified: 2026-01-31 # last time this was confirmed against a source
source: documents/Assets/US/Ally/2026-01-31.statement.pdf   # or "live page", "interview"
---
Prose below. Cite the source for any number.
```

Type-specific fields (use these names exactly):
- **account** — `institution`, `name`, `last4` (quoted string), `owners: [...]`,
  `ledger_account`, `status: active|closed`; optional `kind`, `tax_status`.
- **equity** — `issuer`, `holder`, `platform`.
- **policy** — `line`, `carrier`, `policy_last4`, `insureds: [...]`, `premium`,
  `premium_period`, `effective`, `deductible`, `coverage: {...}`, `status`.
- **person** — `name`, `born`.
- **tax_year** — `year`, `filing_status`.
- **goals** — the machine-read thresholds live in a ```yaml block in the body.

**Watchable dates.** To put a date on the radar, write a bullet
`- YYYY-MM-DD — what happens` under an `## Upcoming` heading in any facts
file. The upcoming report and the deadline check both aggregate every such
bullet. Recurring chores go in `facts/household/calendar.md` as
`- monthly — …` / `- quarterly — …` / `- yearly (Mar) — …` bullets.

## Ledger format
Beancount v3. `main.beancount` includes `accounts.beancount` (every account
opened once, grouped by kind), `prices.beancount`, and one file per year.
Account naming: `Assets:US:<Institution>:<Name><last4>`,
`Liabilities:US:<Institution>:Card<last4>`, `Income:US:<Source>`,
`Expenses:<Category>[:Subcategory]`. Illiquid/paper wealth (private
equity, unvested grants) is priced in the shadow currency named in
`rules.toml` so it can never leak into spendable net worth.

## Answering questions
Read `reports/*.md` first — the answers are precomputed there. For anything
deeper use the query tool (`tools/run query.py networth | balances |
positions | spend | cashflow | payee <regex> | uncategorized | sql "<bql>"`)
rather than eyeballing the ledger. Arithmetic is code; judgment is the agent.

## Rules
- Facts first, opinions second. Read THESIS.md before advising.
- Verify against a source or a live page before stating any dollar figure.
  Never invent a number — mark unknowns explicitly.
- **Account numbers are last-4 ONLY, everywhere.** No SSNs, no credentials.
  The pre-commit scanner blocks any commit that violates this; don't fight
  it — redact. Full numbers live in the password manager, not here.
- Edit surgically. Never regenerate a whole file to change one line.
- History is never deleted: closed accounts get a Beancount `close`
  directive and `status: closed`, not removal. Documents are archived, not
  deleted.
- Commit at the end of every session so the next one starts already knowing.
